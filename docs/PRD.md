## 1. 개요

### 1.1 한 줄 정의

전세·매매 계약 전에 등기부등본과 공공데이터를 **로컬에서** 분석해, 사기·깡통 위험 신호를 근거와 함께 보여주는 **계약 전 점검 도구**.

### 1.2 해결하려는 문제

- 전세사기·깡통전세·매매 사기가 반복되는데, 일반인은 등기부등본(갑구/을구)을 읽고 위험을 판단하기 어렵다.
- 등기부등본에는 개인정보(소유자 정보 등)가 있어 외부 서비스에 올리기 부담스럽다.
- 기존 서비스는 유료이거나 데이터를 서버로 보낸다.

### 1.3 목표

1. 위험 신호를 **결정적(재현 가능한) 룰**로 판정하고, 판정마다 **근거(원문 위치·수치·출처)**를 제시한다.
2. 등기부 원본과 개인정보는 **사용자 PC 밖으로 나가지 않는다.**
3. 운영·사용 비용 **0원** (로컬 실행, 공공데이터 무료 API, LLM은 **사내 모델** 사용으로 추가 비용 없음).
4. LLM은 **보조**(텍스트 구조화·문장 정리)이며, 위험 판정은 LLM이 하지 않는다.
5. 설치부터 첫 리포트까지 **10분 이내**.

### 1.4 비목표 (하지 않는 것)

- 법률·투자·중개 자문 제공 (참고용 점검 도구이며 면책 고지 필수)
- 매물 플랫폼 크롤링 및 차단 우회 (이용약관·법적 리스크)
- 임대인 신용조회, 국세·지방세 체납 직접 조회 (본인 동의 없이 불가능 → 확인 요청 체크리스트로 대체)
- 호스팅 SaaS, 계정/회원, 결제 (v1 범위 밖)
- 위험 "없음"의 보증 (Green은 "탐지된 위험 신호 없음"이지 "안전 보증"이 아님)

### 1.5 타겟 사용자

- 전·월세 또는 매매 계약을 앞둔 2030, 1인 가구, 부동산 초보자
- **v1 배포 범위: 사내망 사용자(사내 구성원)로 한정.** 사외 일반 공개는 v1 범위 밖이다.
- 가정: Docker Desktop을 설치할 수 있거나 설치 가이드를 따라 할 수 있는 사용자 (§12 설치 장벽 참고)

## 2. 제품 모델: 설치형

| 항목        | 결정                                                                                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 실행        | `docker compose up` 으로 로컬 기동, 브라우저에서 `http://localhost:<port>` 접속                                                                               |
| 데이터 저장 | 로컬 볼륨(SQLite)만 사용. 외부 DB·분석·로그 전송 없음                                                                                                         |
| 네트워크    | 외부 호출은 (1) 공공데이터 API, (2) 사내 LLM 엔드포인트(사용자가 켠 경우)뿐. LLM 미설정 시 (1)만                                                              |
| API 키      | 사용자가 각자 공공데이터포털 키를 발급해 `.env` 에 입력. **배포 이미지에 키를 포함하지 않는다**                                                               |
| LLM         | 기본: **사내 모델**(엔드포인트·키를 `.env`로 주입, OpenAI 호환 규격 가정 — 확인 필요). 옵션: 로컬 Ollama, 기타 외부 API. LLM은 선택 기능이며 없어도 전체 동작 |
| 배포 범위   | **사내망 전용.** 사내 컨테이너 레지스트리로 배포. 사용자 환경은 공공데이터 API 등 외부 호출 가능, **사내 LLM만 사내망 한정**                                  |
| 업데이트    | 새 이미지 pull. 룰 버전은 이미지 버전과 함께 리포트에 기록                                                                                                    |

> 호스팅 SaaS는 개인정보처리방침, 로그 정책, 운영 책임이 필요하므로 v1.x 이후 별도 검토. v1의 코드는 호스팅으로 확장 가능하도록 core를 프레임워크와 분리한다(§7).

## 3. 핵심 사용자 시나리오

1. **전세 계약 전 점검**: 사용자가 등기사항전부증명서 PDF 업로드 → 보증금·계약 정보 입력 → 리포트(등급, 위험 신호 목록, 확인할 일).
2. **매물 설명 구조화**: 매물 설명 텍스트를 붙여넣기 → (LLM 또는 규칙) 보증금, 면적, 층, 주소 후보 추출 → 사용자가 확인·수정 후 분석에 사용.
3. **재점검**: 계약일·잔금일 전에 새로 발급한 등기부를 올려 이전 리포트와 **변동사항** 비교(근저당 신규 설정 등).
4. **매매 점검**: 등기부 + 매매가 입력 → 소유권 관련 위험, 근저당 말소 조건 안내.

## 5. 분석 룰 명세

### 5.1 원칙

- 룰은 **순수 함수**: `facts → { 판정, 심각도, 근거, 권장행동 }`. LLM 호출 금지.
- 모든 룰은 ID, 버전, 근거(법령·기관 기준 또는 실무 근거) 주석을 가진다.
- 임계치·기준 금액·배율은 코드에 하드코딩하지 않고 **설정 파일(`rules.config`)** 로 분리하고 출처·시행일을 기록한다.
- **종합 등급**: Red 룰이 하나라도 해당 → Red / 없고 Yellow 룰 해당 → Yellow / 없으면 Green("탐지된 위험 신호 없음"). 점수는 보조 지표이며 등급을 결정하지 않는다.
- 입력이 부족하거나 파싱 신뢰도가 낮으면 해당 룰은 "판단 보류"로 표시하고 Green으로 간주하지 않는다.

### 5.3 LTV 계산 규칙

- **시세 추정**: ① 사용자 입력 시세, ② 최근 실거래(동일 단지·유형·면적 기준) 중앙값, ③ 공시가격 ÷ 현실화율(설정값). 사용한 방식을 리포트에 표기한다.
- **채권최고액 ≠ 실제 대출액.** 기본은 채권최고액 전액 반영(보수적)이며, 추정 실채무(채권최고액 ÷ 설정 배율)를 **참고치로 병기**한다.
- 현실화율, 소액임차인 기준 금액, LTV 임계치는 `rules.config` 에서 지역·시행일별로 관리하고 **출처를 함께 기록**한다. 임계치 초기값은 M0에서 근거 문서(보증기관 기준 등)와 대조해 확정한다.

### 5.4 등기부 파싱 요구사항

- 표제부/갑구/을구 구분, 순위번호별 항목 추출.
- **말소 표시(취소선·"말소" 기재) 항목은 활성 권리에서 제외**하고 별도 이력으로 보관.
- 항목별 **파싱 신뢰도**와 **원문 위치(페이지·줄)** 를 보관하여 리포트에서 근거로 표시.
- 파서 입력이 예상 형식과 크게 다르면 분석을 중단하고 "형식 인식 실패"를 알린다(추정 분석 금지).

### 5.5 대출 가능액 추정 (재무 프로필 기반)

사용자의 자산·소득으로 "이 매물을 감당할 수 있는가"를 계산한다. 위험 등급과는 **별도 섹션**으로 보여주며 등급에 영향을 주지 않는다.

**계산 모델** (모든 비율·기준은 `rules.config`, 규제 시행일·출처 기재)

1. **LTV 기반 한도** = 담보가치(시세) × 적용 LTV 한도 − 기존 선순위 채권(등기부 근저당) − 해당 시 소액임차인 최우선변제금 공제
   - 적용 LTV 한도는 규제지역 여부, 주택 보유 수, 생애최초 여부, 주택 가격 구간에 따라 달라진다(설정 테이블).
2. **DSR 기반 한도** = (연소득 × DSR 한도 − 기존 대출 연 원리금) 을 신규 대출의 만기·금리·상환방식으로 원금 환산
   - 금리는 사용자 입력 + 스트레스 가산 설정값을 반영한 보수 시나리오를 함께 계산한다.
3. **상품·기관 한도**(전세대출은 보증기관 한도, 정책대출 한도 등)를 설정값으로 적용.
4. **추정 대출 가능액 = min(1, 2, 3)**. 어느 항목이 병목인지(LTV/DSR/상품한도)를 표시한다.
5. **자금 조달 갭** = 매매가(또는 보증금) + 부대비용(취득세·중개보수·이사비 등 설정/입력) − 추정 대출 − 보유 자산. 양수면 부족액으로 표시.

**표시 원칙**

- 단일 값이 아니라 **범위(보수/기준)** 로 표시하고, 입력 가정(금리·만기)을 함께 보여준다.
- "실제 대출 한도는 금융기관 심사로 결정되며 본 계산은 참고용 추정"이라는 고지를 항상 표시한다.
- 매물 LTV(§5.3의 위험 지표)와 대출 LTV(이 절의 한도)는 **이름과 화면을 구분**한다.
- 재무 프로필이 없으면 이 섹션은 숨기고 위험 분석만 수행한다.
- 보유 자산·소득은 리포트 **공유용 마스킹 사본에서 제외**한다.

### 5.6 필요 자금 산출 (매매·전세 공통, 재무 프로필 없이도 총액은 표시)

"이 집에 들어가려면 현금이 얼마 필요한가"를 항목별로 보여준다. 세율·요율·수수료는 모두 `rules.config`(출처·시행일 포함)로 관리한다.

| 구분     | 비용 항목                                                                                          |
| -------- | -------------------------------------------------------------------------------------------------- |
| **매매** | 매매가, 취득세(및 부가 세목), 중개보수, 법무사·등기 비용, 채권 매입 비용, 이사·수리비(사용자 입력) |
| **전세** | 보증금, 중개보수, 이사비(사용자 입력), 보증보험료(가입 시), 대출 이자 부담                         |
| **월세** | 보증금, 중개보수, 이사비, 월 임대료(참고)                                                          |

**출력**

1. **총 필요 자금** = 가격(또는 보증금) + 부대비용 합계 (항목별 내역 표시)
2. **필요 자기자금** = 총 필요 자금 − 추정 대출 가능액(§5.5, 범위로 표시). 재무 프로필이 없으면 대출 차감 없이 총액만 표시
3. **자산 대비 과부족** = 보유 자산 − 필요 자기자금 (부족액 또는 여유액)
4. **시점별 현금 필요**: 계약금(통상 비율은 설정값) → 중도금 → 잔금·등기 시점에 각각 필요한 현금 (대출은 잔금 시점에 실행됨을 반영)
5. **월 상환 부담 추정**: 추정 대출액 × 입력 금리·만기 기준 월 원리금, 월 소득 대비 비율

**원칙**

- 보수 시나리오와 기준 시나리오를 함께 보여준다. 입력하지 않은 비용(수리비 등)은 0으로 가정했다고 표시한다.
- 세금·수수료는 매물 유형·가격·보유 주택 수에 따라 달라지므로 적용한 기준과 출처를 표시하고, 정확한 금액은 법무사·세무사·금융기관 확인이 필요하다고 고지한다.
- 위험 등급과 분리된 섹션이며 등급에 영향을 주지 않는다. 위험 등급이 Red이면 이 섹션 상단에 "위험 신호가 있어 자금 계산보다 확인이 먼저" 문구를 표시한다.

## 7. 아키텍처

### 7.1 파이프라인

```
입력(PDF/텍스트/폼)
  → 파서(등기부, 매물 텍스트)           ← 로컬, 결정적 (LLM 구조화는 선택·보조)
  → facts JSON (정규화·신뢰도 포함)
  → 룰 엔진 (순수 함수, 룰 버전 고정)
  → 판정·근거·등급
  → 리포트 렌더러
      └ (선택) LLM 요약 문장 생성 → 스키마 검증 → 실패 시 템플릿 문장
```

### 7.2 모듈 구조 (제안)

```
safehome-report/
├─ src/core/          # 프레임워크 무의존: parsers/, rules/, report/
├─ src/adapters/      # public-data/, llm/ (provider), storage/
├─ src/web/           # Next.js UI + API routes
├─ src/mcp/           # 얇은 MCP 래퍼 (P2)
├─ rules.config/      # 임계치·기준금액·출처·시행일
├─ docs/              # PRD, ADR, 위협모델, 룰 명세
├─ tests/             # fixtures/, golden/, contract/, e2e/
└─ docker/            # Dockerfile, compose
```

### 7.3 기술 스택 (초안)

- Next.js + TypeScript (UI와 로컬 API를 한 프로젝트로)
- PDF: `pdfjs-dist` 텍스트 추출 (브라우저 또는 Node에서 동일 core 사용)
- 저장: SQLite (로컬 볼륨)
- 검증: zod (입력·LLM 출력 스키마)
- 컨테이너: Node Alpine 기반, non-root
- LLM: Ollama(컨테이너) / OpenAI 호환 / Anthropic — Provider 인터페이스로 교체

> 스택은 제안이며 ADR로 확정한다. 확정 전까지 core는 특정 프레임워크에 의존하지 않는다.

## 8. LLM 연동

### 8.1 역할 제한

| 허용                                             | 금지                                                                                |
| ------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 매물 설명 텍스트에서 필드 추출(사용자 확인 전제) | 위험 등급·점수·법적 판단                                                            |
| 리포트 요약 문장 생성(룰 결과를 문장화)          | 수치 계산·권리 해석                                                                 |
| —                                                | 등기부 원문·성명·주민번호 등 입력                                                   |
| —                                                | **자산·연소득·기존 대출 등 재무 프로필 입력** (대출 계산은 룰 엔진이 로컬에서 수행) |

### 8.2 Provider 인터페이스

```
generate({ system, input, schema, timeoutMs }) → Validated JSON | Error
```

- 구현체: `internal`(사내 모델, 기본·OpenAI 호환 가정), `ollama`, `anthropic`. 환경변수로 선택.
- 사내 모델도 **사용자 PC 밖 네트워크 구간**이므로 외부 Provider와 동일하게 취급한다: 설정에서 명시적으로 켜고, 전송 필드 목록을 UI에 표시한다. 사내 전용 정책(로그 보관 등)은 사내 모델 운영 측 정책에 따른다.
- LLM 엔드포인트에 접근할 수 없는 환경(사내망 밖 등)이나 장애 시 **LLM 없이 전체 기능 동작**(템플릿 문장).

### 8.3 안전 장치

- **입력 화이트리스트**: LLM에는 정규화된 facts의 허용 필드만 전달. 원문·성명·상세주소 제외.
- **Prompt injection 대응**: 매물 설명 등 외부 텍스트는 "데이터" 구획으로 감싸 전달하고, LLM에 판정 권한이 없으므로 출력이 오염되어도 등급은 변하지 않는다. LLM 출력의 등급·수치 필드는 룰 결과와 불일치 시 폐기.
- 출력은 JSON 스키마(zod) 검증 → 실패 시 1회 재시도 → 그래도 실패하면 템플릿 폴백.
- 타임아웃, 동시 요청 큐(로컬 GPU/CPU 보호), 동일 입력 해시 캐시.
- 프롬프트는 파일로 버전 관리하고 리포트에 프롬프트 해시를 기록한다.

### 8.4 로컬 모델 요구사항

- 사내 모델 사용 시 로컬 사양 요구는 없다. 로컬 Ollama를 쓰는 경우에만 권장 사양과 예상 응답시간을 설치 가이드에 명시(M0 실측).
- 사내 모델의 호출 한도(rate limit)·최대 컨텍스트·응답 지연을 M0에서 확인해 타임아웃·큐 설정에 반영한다.

## 9. 비기능 요구사항

### 9.1 보안·프라이버시

1. 등기부 PDF·원문 텍스트·성명은 **디스크에는 사용자 로컬 볼륨에만**, 외부 네트워크(LLM 포함)로는 **전송하지 않는다.**
2. 서버 로그에 개인정보 금지(주소·성명은 해시 또는 마스킹). 로그 레벨 정책을 둔다.
3. 컨테이너: non-root, 읽기 전용 파일시스템 가능 범위 적용, 포트는 `127.0.0.1` 바인딩 기본.
4. API 키는 `.env` / Docker secret. 이미지·저장소에 키 금지(커밋 전 secret-scan).
5. 이미지 취약점 스캔(trivy)과 의존성 감사를 릴리즈 전 필수 수행.
6. 이력 데이터는 사용자가 한 번에 삭제 가능(전체 삭제 버튼, 볼륨 삭제 안내).
7. 공유용 사본은 기본 마스킹.

### 9.2 성능 목표 (참고 기준, M0에서 실측 후 확정)

| 항목                  | 목표                                              |
| --------------------- | ------------------------------------------------- |
| 등기부 PDF 파싱       | 일반 PDF 2초 이내                                 |
| 룰 판정(캐시 적중)    | 1초 이내                                          |
| 공공API 호출          | 건당 타임아웃 3초, 재시도 2회(backoff), 병렬 호출 |
| 전체 리포트(LLM 제외) | 5초 이내                                          |
| LLM 요약              | 비동기 진행 표시, 상한 시간 초과 시 템플릿 대체   |
| 설치~첫 리포트        | 10분 이내                                         |

### 9.3 신뢰성·관측

- 외부 API·LLM 장애 시 **부분 결과 + 사유 표시**로 계속 진행(전체 실패 금지).
- 단계별 소요 시간·실패 원인을 로컬 로그로 남긴다(PII 제외).

### 9.4 호환성

- Docker Desktop(macOS/Windows), Linux Docker. Apple Silicon·x86 멀티 아키텍처 이미지.

## 10. 법적·정책 고려

- 모든 화면·리포트에 **참고용 고지**를 표시한다: 법률·중개·투자 자문이 아니며, 계약 전 법무사·변호사·보증기관 상담을 권장한다.
- 단정 표현("입금하지 마세요")은 쓰지 않고 "위험 신호가 있어 계약 진행 전 아래 사항 확인을 강력히 권장" 형태로 쓴다.
- 매물 플랫폼 크롤링·차단 우회 기능은 제공하지 않는다.
- 공공 API 이용약관(출처 표시, 일일 한도, 상업 이용 조건)을 M0에서 확인하고 문서화한다.
- 개인정보처리방침 대신 **"데이터가 PC 밖으로 나가지 않는다"는 데이터 흐름 문서**를 배포물에 포함한다.

| 레벨    | 대상           | 방법                                                                                                      |
| ------- | -------------- | --------------------------------------------------------------------------------------------------------- |
| L1 단위 | 룰 엔진        | 골든셋(입력 facts → 기대 판정), 임계치 경계값, 말소 항목 케이스                                           |
| L2 파서 | 등기부 PDF     | 개인정보를 제거한 샘플 PDF → 기대 facts JSON 스냅샷                                                       |
| L3 계약 | 공공API 어댑터 | 녹화 응답(MSW/nock)으로 CI 실행. 실 API 스모크는 수동/주기 실행                                           |
| L4 LLM  | 요약·추출      | 스키마 준수율, 금지 표현·숫자 불일치 검사, prompt injection 회귀 케이스. 외부 유료 API는 릴리즈 전 수동만 |
| L5 E2E  | 전체 흐름      | `docker compose up` → Playwright로 업로드~리포트                                                          |
| 보안    | 로그·네트워크  | 로그 PII 누출 검사, LLM 전송 페이로드 필드 검사, 컨테이너 egress 점검                                     |

- 룰 변경 PR은 **골든셋 갱신과 근거 문서**가 없으면 병합하지 않는다.
- 골든셋은 도메인 전문가(공인중개사·법무사) 검토를 받는 것을 목표로 한다.

### 11.2 설계 검수

- **ADR**(`docs/adr/NNNN-제목.md`): 제품 모델, LLM 공급자, 스택, 임계치 근거 등 결정마다 기록.
- **위협 모델(STRIDE) 1장**: 데이터 흐름도와 신뢰 경계(로컬 ↔ 공공API ↔ 외부 LLM).
- **PR 체크리스트**: 룰 변경 근거, 외부 호출 추가 시 보안 검토, 로그 PII 없음, 설정값 출처 기재.
- 정기: 코드 리뷰와 보안 리뷰(PR 단위), 의존성 점검(월 1회 및 릴리즈 전).

## 12. 배포·릴리즈

### 12.1 배포

1. **사내 컨테이너 레지스트리**(사내망 전용)에 멀티아키텍처 이미지 게시. 외부 공개 레지스트리에는 올리지 않는다. 소스 저장소도 사내 정책에 따른다.
2. 배포 산출물: `docker-compose.yml`, `.env.example`, 설치 가이드, 데이터 흐름 문서.
3. compose 프로파일: 기본(앱) / `llm`(Ollama 포함).
4. 공공데이터 키 발급 안내 문서 제공(사용자 각자 발급).
5. 설치 장벽 완화: 원라인 설치 스크립트(P2), 데스크톱 패키징은 v1 이후 검토.

### 12.2 버전·커밋 규칙

- **SemVer**: 0.x 동안 minor=기능, patch=수정. 1.0은 §14 출시 기준 충족 시.
- 태그 `vX.Y.Z`와 릴리즈는 **사용자에게 배포할 때만** 생성.
- 커밋: 기존 커밋 규칙(`type(scope)` 한글 제목, 파일별 줄, 작업일시, push 후 CHANGELOG) 준수.
- 브랜치: `main` 보호, `feature/*`·`fix/*` 짧은 브랜치, 작은 PR.
- **룰셋 버전**을 별도 관리(`ruleset-vN`). 룰·임계치 변경은 판정이 바뀌므로 릴리즈 노트에 필수 기재.
- 릴리즈 전 체크: 테스트 전체 통과, trivy/의존성 감사, secret-scan, 릴리즈 노트 작성, 롤백 가능한 이전 이미지 태그 유지.

## 16. 용어

- **갑구**: 소유권에 관한 사항. **을구**: 소유권 외 권리(근저당 등)에 관한 사항.
- **채권최고액**: 근저당권으로 담보되는 최대 금액(실제 대출액과 다름).
- **LTV(여기서는)**: (선순위 채권최고액 + 보증금) ÷ 시세.
- **대항력**: 전입신고와 점유로 제3자에게 임차권을 주장할 수 있는 효력.
- **골든셋**: 입력과 기대 판정을 짝지은 회귀 테스트 데이터.

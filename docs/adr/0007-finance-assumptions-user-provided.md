# ADR-0007: 대출·세금 기준값은 사용자 입력, 앱은 계산만

- 상태: 승인
- 날짜: 2026-11-06

## 맥락

대출 가능액과 필요 자금 계산에는 LTV·DSR 한도, 스트레스 금리, 취득세율, 중개보수 요율, 보증료율 등이 필요하다. 이 값들은 규제지역, 주택 수, 생애최초 여부, 금융기관·상품, 시행일에 따라 달라지고 자주 바뀐다. 현행 값을 앱이 확정적으로 보유하면 틀린 값으로 "그럴듯한 숫자"를 보여줄 위험이 있다.

## 결정

- `src/core/finance` 는 **계산 로직만** 제공하고 기준값 기본값을 두지 않는다. 입력 스키마에서 대출 기준값(`loan`)은 필수이며 누락 시 거부한다.
- 부대비용 요율은 선택 입력이고, 입력하지 않은 항목은 0원으로 계산한다. 리포트는 이 가정을 표시해야 한다.
- 금액·비율 계산은 원 단위 정수와 BigInt 기반 `mulPercent`(내림)로 하고 부동소수점 오차를 피한다(ADR-0004). 상환액 계산은 원리금균등 공식을 쓰며 월 상환액은 올림, 역산 원금은 내림으로 보수적으로 처리한다.
- 기준·보수 두 시나리오를 제공한다. 보수 시나리오는 DSR 계산 금리에 가산 금리를 더한다.
- 대출은 가격(보증금)까지만 반영하고 부대비용은 자기자금으로 충당한다고 단순화한다. 대출은 잔금 시점에 실행된다고 본다.
- UI(`src/web/financeForm.ts`)는 모든 대출 기준값을 빈 칸으로 시작하고, 필수값이 비면 계산하지 않는다. 담보가치는 매매는 매매가·시세 중 낮은 값, 전세·월세는 보증금으로 정하고 선순위 채권은 차감하지 않는다(매도인의 기존 근저당은 잔금 때 말소되고 전세대출 한도와도 무관하다고 가정). 재무 정보는 저장·전송하지 않는다.
- 사용자가 값을 입력할 때 공식 출처(금융당국·보증기관 안내)를 함께 안내한다. 공식 값을 번들에 넣게 되면 `rules.config` 에 `source`/`status` 와 시행일을 붙여 별도 ADR로 결정한다.

## 결과

- 앱이 틀린 규제 값을 보증하는 상황을 피한다. 대신 사용자가 값을 직접 입력해야 하는 사용성 부담이 있다.
- 계산은 순수 함수라 골든셋으로 검증할 수 있다. 계산 결과는 "추정치이며 실제 한도는 금융기관 심사로 결정"이라는 고지와 함께 표시한다.

## 개정 (2026-11-09): 필요 조건 역산, 예시 값 버튼

- 사용자가 가장 알고 싶은 것은 "이 가격이면 연소득과 자산이 얼마나 필요한가"이므로, 내 재무 정보 없이 **필요 조건을 먼저 계산**한다(`evaluateRequirements`). 입력한 LTV·DSR·금리·기간 가정으로 최대 대출, 필요 자기자금, 월 상환액, 필요 연소득(= (신규+기존 연 원리금) ÷ DSR 한도)을 대출 비율(100/80/60/40/20/0%)별로 보여준다. 정방향 계산(`evaluateAffordability`)과 서로 맞는지 테스트로 확인한다.
- 보유 자산·연소득은 선택 입력이다. 둘 다 입력하면 "내 상황" 판정도 함께 보여주고, 하나만 입력하면 오류로 안내한다.
- 대출 기준값은 여전히 필수이며 기본값이 없다. 입력 부담을 줄이기 위해 **사용자가 버튼을 눌렀을 때만** 빈 칸을 예시 값으로 채우는 버튼을 둔다. 예시는 공식 값이 아니며 화면에 그렇게 표시한다. 리포트에는 "입력하신 가정으로 계산한 추정치"임을 항상 밝힌다.

## 개정 (2026-11-09): AI 기준값 제안

사용자가 "지역·집마다 다른 기준값을 AI가 계산하길 원한다"고 정했다. 다만 AI는 최신 규제를 모르고 틀린 숫자를 그럴듯하게 낼 수 있으므로, **AI는 제안만 하고 판단·계산은 하지 않는다.**

- 대상은 지역·보유 주택 수·생애최초 여부에 따라 달라지는 **대출 기준값(LTV·DSR·금리·스트레스 가산·기간)** 뿐이다. 세금·중개보수는 법정 계산(`taxes.ts`)이 하므로 AI에게 맡기지 않는다.
- 안전장치: 모르면 `null`, 신뢰도는 `low`/`medium` 만 허용(스키마에서 `high` 거부), 범위 검증(`sanitizeAssumptions`), 지역 입력은 `<request>` 구획과 길이 제한(50자), 소득·자산·성명은 전송하지 않음.
- 사용자가 확인하고 "적용"을 눌렀을 때만 입력 칸이 채워진다. 적용된 **칸 이름을 기록**(`aiFields`)해 리포트에 "다음 대출 기준값은 AI가 제안한 값입니다: …"를 표시한다. 사용자가 그 칸을 직접 고치면 그 칸만 표시에서 빠지고 나머지는 유지된다.
- 실제 모델로 시험한 결과, 모델은 지침대로 확실하지 않은 값을 `null` 로 두어 **일부 칸(DSR·기간)만 제안**했다. 값을 더 많이 채우도록 프롬프트를 느슨하게 하면 틀린 숫자를 사실처럼 낼 위험이 커지므로, 현재는 보수적인 동작을 유지한다.

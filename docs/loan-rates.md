## 대출 대상 요건 (추천용)

화면의 "대출 추천" 시트는 [`rules.config/loan-eligibility.json`](../rules.config/loan-eligibility.json) 의 요건으로 입력값을 판정합니다. 주택도시기금 공식 상품 페이지의 **대출대상·대상주택** 항목(소득 상한, 순자산 상한, 나이, 혼인·출산 요건, 보증금·주택가격 상한, 전용면적, 월세 상한)만 담았고 상품마다 출처 링크와 확인일(2026-11-12)이 있습니다. 순자산 상한(전세류 3.45억원, 구입류 5.11억원)은 통계청 가계금융복지조사 평균에 연동돼 해마다 바뀝니다. 한도·LTV·DTI·가산금리 계산은 이 데이터의 범위가 아니며, 요건이 바뀌면 `npm run rates:check` 와 별개로 공식 페이지에서 직접 확인해 이 파일을 고쳐야 합니다. `npm run rates:check` 가 요건의 금액(소득·순자산·보증금·월세 상한), 전용면적, 나이가 공식 페이지에 그대로 적혀 있는지도 확인해, 값이 사라지면(예: 순자산 상한이 바뀌면) 알려 줍니다. 페이지 문구가 아닌 조건(혼인 기간 등)은 점검하지 않습니다(2026-11-12 첫 실행: 8개 상품 모두 일치).

## 확인하지 못한 것

- **시중은행의 실제 적용 금리**: 은행연합회 공시는 직전 달 신규 취급 대출의 신용점수 구간별 평균이라 내 조건에 실제로 적용될 금리와 다를 수 있습니다(우대금리·보증기관·상환 방식·한도에 따라). 최종 금리는 은행에 확인하세요. 신용점수 구간에 표본이 없으면 "-" 입니다.
- **신생아 특례 상품의 특례금리 적용 종료 후 금리**: 종료 후에는 은행 기준금리와 소득에 따라 달라지는 별도 표라 담지 않았고 화면에 "공식 페이지에서 확인"으로 안내합니다.
- **주거안정월세대출·청년전용 보증부월세대출의 한도·요건·가산금리 수치**: 금리 외에는 담지 않았습니다.
- 상품별 한도·소득·자산 요건은 이 데이터의 범위가 아닙니다.

조사 과정에서 웹 페이지 본문을 요약 도구로 가져왔기 때문에, 숫자는 **공식 페이지 원문과 한 번 더 대조**하는 것이 안전합니다(링크 제공). 보금자리론은 같은 페이지의 이전 공시(2026-11-01, 0.1%p 낮음)와 검색에서 본 10월 표와 값이 서로 일관됨을 확인했습니다.

## 화면 동작

- 상품마다 금리, 가산·우대 규칙, **출처 링크와 확인일**을 보여줍니다.
- 확인일이 **35일**을 넘으면 "확인한 지 N일이 지났습니다. 금리가 바뀌었을 수 있으니 다시 확인하세요" 경고를 띄웁니다(`STALE_AFTER_DAYS`).
- 데이터가 없는 상품은 "공식 자료를 확인하지 못했습니다. 취급 기관의 안내 금리를 확인하세요"로 안내합니다.

## 데이터 갱신 방법

값을 자동으로 고치지는 않습니다(잘못된 값이 조용히 들어가는 것을 막기 위해). 대신 **점검 스크립트**가 현재 공식 사이트 값과 저장값을 비교해 차이만 알려 줍니다.

```bash
npm run rates:check
```

- 주택도시기금 상품 7개(버팀목·신혼부부·디딤돌·신생아 특례 2종의 칸별 표, 월세 2종)를 공식 사이트에서 읽어 `rules.config/loan-rates.json` 과 비교하고, 대출 추천에 쓰는 대상 요건 8개도 `loan-eligibility.json` 과 비교합니다. 파일은 수정하지 않습니다(읽기 전용).
- 종료 코드 0 이면 모두 일치, 1 이면 차이 또는 확인 실패입니다. 어느 칸이 얼마에서 얼마로 바뀌었는지 출력합니다.
- 보금자리론·COFIX·청년전용 버팀목처럼 스크립트가 보지 않는 상품은 확인일이 35일을 넘었는지만 알려 주니 해당 공식 페이지에서 직접 확인하세요.
- 차이가 나오면 공식 페이지에서 직접 확인한 뒤 아래 1~3 순서로 고칩니다. 사이트 구조가 바뀌어 "읽지 못했습니다"가 나오면 `scripts/loanRateCheck.mjs` 의 읽기 규칙을 고쳐야 합니다.
- 2026-11-12 첫 실행: 7개 상품 모두 저장값과 일치했습니다.

월 1회 정도 위 명령을 실행하고, 차이가 있을 때만 갱신하세요.

**시중은행 금리**는 매달 바뀌는 공시라 갱신을 스크립트로 돕습니다.

```bash
npm run rates:banks              # 최신 공시월의 은행별 평균금리를 표로 출력
npm run rates:banks -- --write   # rules.config/loan-rates.json 의 bank-jeonse·bank-mortgage 에 반영
```

- 은행연합회 비교공시 페이지가 검색 버튼을 누를 때 보내는 요청(`POST /compare/loan_household_new_search_result_new.php`, 응답은 EUC-KR HTML 표)과 같은 요청으로 받아 읽습니다(2026-11-13 확인). 직전 달부터 최대 3개월 전까지 금리가 있는 가장 최근 공시월을 씁니다.
- `--write` 는 파일을 고치므로 반드시 `git diff` 로 검토한 뒤 `npx prettier --write rules.config` 를 돌리고 커밋하세요. 사이트 구조가 바뀌면 "은행 목록을 읽지 못했습니다"로 멈춥니다.

> 주택도시기금(nhuf.molit.go.kr) 상품 페이지의 칸별 금리표는 HTML 이 아니라 페이지의 스크립트가 `POST /init/include/NewBabyGetInform.jsp` 로 받아 채웁니다(공식 사이트가 자기 페이지에서 쓰는 요청). 요청 값은 버팀목 `newBabyGetBuySelect=newMearryHouseRent&productgb=N`, 신혼 `newMearryHouseRent&productgb=Y`, 디딤돌 `newMearryHouse&productgb=F` 이고, 응답의 `LOANRATE`, `LOANRATE1`, … 이 표의 칸을 왼쪽 위부터 행 순서대로 채웁니다(2026-11-11 확인). 신생아 특례는 `productgb=S` 이고 버팀목 `newMearryHouseRent`, 디딤돌 `newMearryHouse` 입니다(36칸 = 연소득 9행 × 4열, 2026-11-12 확인, 페이지의 "연 1.3%~4.3%"·"1.8% ~ 4.5%" 문구와 최저·최고가 일치). 월세 두 상품은 금리가 페이지 본문에 글로 적혀 있습니다.

1. 위 표의 출처 링크에서 현재 금리를 확인하고 `rules.config/loan-rates.json` 의 값과 `source.checkedAt`(필요하면 `publishedAt`)을 고칩니다. 보금자리론은 매월 공시되고 COFIX 는 매월 15일경 공시됩니다.
2. `npm test` 를 실행합니다. 스키마가 **공식 도메인이 아닌 출처**(블로그 등), https 가 아닌 링크, 0 이하·15% 초과 금리, 만기 수와 금리 수가 다른 표를 거부합니다.
3. 이 문서의 표와 확인일도 함께 고칩니다.

# SafeHomeReport (가칭)

**전세·매매 계약을 하기 전에, 매물 조건만으로 위험 신호를 먼저 점검하는 로컬 도구.**

계약서나 등기부가 없어도 보증금과 시세만으로 1차 판정을 하고, 등기부 내용을 넣으면 권리분석까지 합니다.
위험 판정은 계산 규칙이 하고, AI는 매물 설명에서 항목을 뽑는 데에만 씁니다. 분석 계산은 내 PC의 브라우저 안에서만 이루어집니다.

> 참고용 점검 도구이며 법률·중개·투자 자문이 아닙니다. 계약 전 법무사·변호사·보증기관 상담을 권장합니다.
> "탐지된 위험 신호 없음"은 안전을 보증하지 않습니다.

## 이런 결과가 나옵니다

2026-11-09에 실제로 실행한 결과입니다.

**매물을 보러 가기 전, 등기부 없이** — 전세 보증금 14억 5천만 원, 삼성동힐스테이트 1단지 전용 31.4㎡

```text
시세   15억 9,000만원  (공공 실거래 최근 12개월 17건의 중앙값, 최저 11.8억 ~ 최고 17.3억)
결과   ⛔ 위험
근거   R-RATIO-01  보증금 14.5억 / 시세 15.9억 = 91.2%
       선순위 근저당을 알 수 없어 보증금만으로 계산한 하한값입니다. 등기부를 확인하면 더 높을 수 있습니다.
행동   방문 전에 가격 조정 가능성과 보증보험 가입 가능 여부부터 확인하세요.
```

**이 가격이면 무엇이 필요한가** — 보증금 5억 원, 예시 가정(LTV 70%·DSR 40%·금리 4%·30년, 공식 값 아님)

```text
대출 최대 3억 5,000만원 (한도를 정하는 항목: LTV)
 → 대출을 최대로 받으면 자기자금 1억 5,000만원 이상, 연소득 5,012만원 이상 필요
```

대출을 100·80·60·40·20·0%로 받을 때의 필요 자기자금·월 상환액·필요 연소득을 한 표로 비교합니다.

## 주요 기능

- **사전 점검 (등기부 없이)**: 보증금/시세 비율로 방문 전에 위험·주의를 판정합니다. 시세는 공공 실거래(아파트 매매) 중앙값으로 조회하거나 직접 입력합니다.
- **권리분석 (등기부 입력·붙여넣기)**: 소유자 불일치, 신탁, 압류·가압류·가처분·경매·임차권등기명령, 잦은 소유권 이전, 근저당 합산과 담보 비율, 대항력 기준일을 봅니다. 말소된 항목은 제외합니다.
- **매물 설명 AI 추출 (선택)**: 붙여넣은 설명에서 유형·보증금·단지명·면적·층·주의 문구를 뽑아 보여주고, 확인한 뒤에만 입력칸에 적용합니다.
- **필요 조건 역산**: 이 가격에 필요한 자기자금·연소득·최대 대출, 내 자산·소득을 넣으면 내 상황 판정까지 보여줍니다.
- **AI 기준값 제안 (선택)**: 지역·보유 주택 수·생애최초 여부에 따라 달라지는 LTV·DSR·금리·기간을 AI가 일반적인 수준으로 제안합니다. 공식 값이 아니므로 확인 후에만 적용되고 리포트에 "AI 제안"으로 표시됩니다.
- **세금·수수료 자동 계산 (잠정)**: 취득세(지방교육세·농어촌특별세 포함)와 중개보수 상한을 법정 요율로 계산합니다.
- **대출 종류와 공식 금리 안내**: 계약 유형별 대출 종류, 확인할 점, 공식 사이트에서 확인한 금리를 출처 링크와 확인일과 함께 보여줍니다(확인일이 오래되면 경고).
- **상세 리포트 팝업**: 근거·권장 행동·체크리스트를 팝업으로 보여주고 인쇄할 수 있습니다.
- **정직한 판정**: 정보가 부족하면 Green 대신 **판단 보류**로 표시합니다.

## 입력별로 알 수 있는 것

| 입력                           | 알 수 있는 것                     | 아직 알 수 없는 것                       |
| ------------------------------ | --------------------------------- | ---------------------------------------- |
| 보증금(매매가)만               | 필요 자금(취득세·중개보수 포함)   | 위험 여부                                |
| + 시세 (실거래 조회 또는 직접) | 보증금/시세 비율로 사전 점검 판정 | 선순위 근저당, 소유자                    |
| + 등기부 내용 직접 입력        | 권리분석 전체, 담보 비율          | 임대인 체납(확인 요청 체크리스트만 제공) |
| + LTV·DSR·금리·기간            | 최대 대출, 필요 자기자금·연소득   | 실제 은행 심사 결과                      |
| + 보유 자산·연소득             | 내 상황이 충분한지 판정           | —                                        |

## 설치

요구 사항: **Docker**(권장) 또는 **Node.js 20 이상**

### Docker로 실행

```bash
docker compose up -d --build
```

브라우저에서 <http://127.0.0.1:3000> 을 엽니다. 포트는 내 PC(127.0.0.1)에만 열리고, 컨테이너는 non-root·읽기 전용 파일시스템으로 실행됩니다.

```bash
docker compose logs -f web   # 로그 보기
docker compose down          # 중지
```

### 로컬에서 실행

```bash
npm install
npm run dev
```

## 빠른 시작

1. 실행한 뒤 <http://127.0.0.1:3000> 을 엽니다.
2. 보증금과 추정 시세(만원 단위)를 입력하고 **분석하기**를 누르면 상세 리포트가 팝업으로 열립니다.
3. (선택) `.env.example` 을 `.env` 로 복사해 키를 넣으면 기능이 늘어납니다.
   - `PUBLIC_DATA_API_KEY` → "실거래가로 시세 조회"
   - `LLM_*` → "AI로 항목 추출"

키 없이도 시세와 항목을 직접 입력해 사용할 수 있습니다. 키 발급과 설정은 [docs/operations.md](docs/operations.md), 공공데이터 API는 [docs/public-data-api.md](docs/public-data-api.md)를 보세요.

## 지금 되는 것과 안 되는 것

- 실거래 시세 조회는 **아파트 매매**만 실제 응답으로 검증했습니다. 빌라(연립·다세대)와 오피스텔 조회는 별도 API 활용신청이 필요하고 응답 필드를 확인하지 못한 **미검증** 기능이며, 다가구·단독은 시세를 직접 입력하세요.
- **등기부 PDF 파일을 직접 읽지는 않습니다.** PDF에서 복사한 텍스트를 붙여넣으면 입력칸을 채워 주지만(브라우저 안에서만 분석), 실제 문서로는 아직 검증하지 못했고 취소선만 있는 말소 표시는 구분하지 못합니다. 채워진 값을 원문과 대조하세요.
- **매물 링크의 내용은 읽지 않습니다.** 플랫폼 약관·차단 때문에 링크에서는 사이트와 매물 번호만 인식하고, 항목은 붙여넣은 설명에서 추출합니다.
- **재산세는 공시가격을 넣으면 잠정값으로 계산하지만, 종합부동산세는 계산하지 않습니다.** 재산세 세율표는 2차 자료 기준이고 세부담상한을 반영하지 않으며, 종부세는 세제 개편이 진행 중입니다.
- 취득세는 **일반 세율**만 계산합니다. 다주택·조정대상지역 중과와 감면은 반영하지 않으며, 중과 세율은 직접 입력할 수 있습니다. 중개보수 요율표는 서울시 조례 원문을 확인하지 못해 **잠정값**입니다.
- 판단 기준 일부(예: 보증금/시세 70%·80%)는 공식 자료로 검증되지 않은 **잠정값**입니다. 리포트에도 같은 안내가 나옵니다.
- **AI 기준값 제안은 확실하지 않은 값을 비워 둡니다.** 실제로 시험해 보니 DSR 40%·기간 30년 정도만 채우고 LTV·금리는 "판단하지 못함"으로 답하는 경우가 많았습니다. 빈 칸은 직접 입력하세요.
- **대출 금리는 확인일(2026-11-09) 기준 공식 안내를 옮긴 것**이며 수시로 바뀝니다. 일반 버팀목·신혼부부 전세자금·디딤돌은 칸별 금리표를 확인하지 못해 범위만, 시중은행은 실제 금리를 확인하지 못해 기준금리(COFIX)만 보여줍니다. 월세 대출·신생아 특례는 금리를 확인하지 못했습니다. 자세한 내용은 [docs/loan-rates.md](docs/loan-rates.md). 계산용 LTV·DSR·금리는 직접 입력하거나 "예시 값 채우기"(공식 값 아님)·AI 제안을 씁니다.

진행 상황은 [로드맵](docs/ROADMAP.md)에서 봅니다.

## FAQ

<details>
<summary>링크만 넣으면 왜 분석이 안 되나요?</summary>

앱이 매물 사이트의 페이지를 대신 열어 읽는 것은 약관과 차단 문제로 하지 않습니다. 매물 화면의 설명을 복사해 붙여넣으면 AI가 항목을 뽑아 줍니다. 설명 없이 링크만 입력하면 서버를 호출하지 않고 화면에서 안내만 합니다.
</details>

<details>
<summary>왜 "안전"이라는 결과가 없나요?</summary>

입력한 정보로는 위험 신호를 찾지 못해도 안전을 보증할 수 없습니다. 그래서 위험 신호가 없으면 "탐지된 위험 신호 없음"으로, 정보가 부족하면 "판단 보류"로 표시하고, 계약 당일과 잔금 전 등기부 재확인을 안내합니다.
</details>

<details>
<summary>내 정보는 어디로 가나요?</summary>

위험 점검과 자금 계산은 브라우저 안에서만 실행됩니다. 서버로 나가는 것은 세 가지뿐이고 모두 직접 버튼을 눌렀을 때만 전송됩니다. 시세 조회는 법정동코드·전용면적·단지명을 공공데이터포털로, 항목 추출은 붙여넣은 매물 설명을 LLM 서버로(전화번호·이메일은 제거), 기준값 제안은 계약 유형·보증금(매매가)·지역·보유 주택 수·생애최초 여부를 LLM 서버로 보냅니다. 성명·금액·재무 정보·등기부 내용은 보내지 않고 서버 로그에도 남기지 않습니다. 자세한 내용은 [위협 모델](docs/threat-model.md)을 보세요.
</details>

<details>
<summary>로그는 어떻게 보나요?</summary>

`docker compose logs -f web` 으로 봅니다. 요청 번호·소요 시간·건수·결과만 한 줄 JSON 으로 남습니다. 형식과 `LOG_LEVEL` 은 [docs/operations.md](docs/operations.md)에 있습니다.
</details>

## 개인정보와 보안

- 분석 계산은 브라우저에서만 실행되고, 입력한 값은 저장하지 않습니다. 체크리스트의 체크 상태만 브라우저에 저장합니다.
- 키·엔드포인트는 로컬 `.env` 에만 두며 저장소와 이미지에는 들어가지 않습니다(`.gitignore`, `.dockerignore`).
- 위험 판정은 계산 규칙이 하고 AI는 판정하지 않습니다. AI 출력은 형식·범위를 검증하고 사용자가 확인해야 적용됩니다.

## 개발

```bash
npm run check          # 타입 검사 + 린트 + 테스트 (249개)
npm run build          # 프로덕션 빌드
npm run format:check   # 포맷 검사
```

위험 판정 규칙은 `src/core`(순수 함수), 화면은 `src/web`·`src/app`, 외부 호출은 `src/adapters` 에 있습니다. 구조와 설계 결정은 [아키텍처](docs/architecture.md)와 [ADR](docs/adr/)에, 기여·커밋·릴리즈 규칙은 [CONTRIBUTING](CONTRIBUTING.md)에 있습니다.
